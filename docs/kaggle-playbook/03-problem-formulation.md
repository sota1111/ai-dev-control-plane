# 3. 問題の定式化

**チューニング以前に、問題の立て方で勝敗が決まる**ことがある。ROGII 2位はここで差をつけた。

## F1. 曖昧なタスクで単一点を回帰すると「モード平均」で負ける
- ROGII の GR マッチは**本質的に多峰(multi-path)**: typewell GR は似た縞の繰り返しで、局所的に
  複数の深度仮説が等価にマッチする。
- **単一 teacher path を回帰するモデルは、複数モードの平均＝どの仮説とも一致しない path に収束**する
  （2位著者が初期実験で確認）。我々の「物理＋ML 点ブレンド」は**重みをどう振っても勝てない定式化**だった。
- **教訓**: 出力に多峰性・曖昧性があるタスク（軌跡、対応付け、セグメンテーション境界、順位）では、
  **点推定を疑う**。まず「この問題の出力は単峰か？」を問う。

## F2. 正解＝条件付き分布 + 厳密デコード
- 2位: 各深度仮説で「次区間の移動量」の**離散分布 P(dTVT|TVT)** を全仮説同時に保持（AnchorCNN）。
- デコードは**動的計画法で期待 path を厳密に周辺化**（sampling 無し）:
  `p_{k+1}(s) = Σ_{s'} p_k(s')·P(dTVT=s−s' | anchor(s',k))`, `pred(k)=Σ_s p_k(s)·val(s)`。
- Viterbi（最尤 path）やモード追跡は**むしろ悪化**。期待値デコードが最良。
- rollout バンドル + reranker/RL で「良い path を選ぶ」は**選抜器が評価データに過学習**して却下された
  （oracle は数ft 良いが再現不能）。→ **選抜より周辺化（期待値）**。

## F3. 問題の恒等式・物理制約を先に見つけて埋め込む
- 2位は恒等式 `dTVT = dz_layer − dz`（z はテスト時も既知）を発見し、dip z を入力特徴に追加。
  これでモデルの仕事が「滑らかな構造 slope 推定」に縮小し、最大レバー（public −1.089）になった。
- **後付けの較正層より、問題構造を特徴・内部表現に埋め込む方が汎化する**。
  内部表現を恒等式が保存される形（2位は z_layer 表現）にすれば、augmentation でも制約が壊れない。

## F4. 合成データは「生成仮定」から作る（free-form 禁止）
- 2位: `GR_obs = f(TVT) + r`（TVT の関数）という生成仮定から、任意の TVT 軌跡に対し**無限に整合データ**を生成。
- ただし**実在しない曲線を食わせると偽特徴を学ぶ** → 実軌跡の mixup + 再配置（re-skinning）で
  現実的な形状のみ生成。残差 `r = δ_w(TVT) + ε`（坑井固有平均 + AR ノイズ）を実データから注入。
- **教訓**: 合成/augmentation は「データ生成過程の物理」に忠実に。分布外の入力は過学習源。

## F5. 「効かなかった」も設計の分岐点として記録する
- 2位が捨てた道: (a) rollout+reranker/RL（過学習）、(b) 明示的 formation モデリング（破滅ケースを治せず、
  expert label は formation 直接参照でなく GR マッチの相対判断だったため）。
- **何が効かないかの理由**が、次の設計を決める。実験台帳に hypothesis と evidence を必ず残す。
