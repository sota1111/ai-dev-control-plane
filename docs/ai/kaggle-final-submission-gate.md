# 最終提出2枠の選定ゲート手順書（SOT-1904）

Kaggle コンペ **`pokemon-tcg-ai-battle`** の最終評価には **直近2提出のみ**が反映される（+ 1日5提出
上限）。計測目的の提出が挟まるたびに最終2枠が意図せず入れ替わるリスクがあるため、どの agent を
最終2枠に置くかの選定手順と、下位枠を入れ替える判定ゲートをここに明文化する。

- 親Issue: SOT-1901（debate を統合チャレンジャーへ再構築し最終2枠入りを狙う）
- 前提Issue: SOT-1902（debate=fable champion 実効同一の切り分け）/ SOT-1903（debate 統合選定＝非昇格・
  champion 維持）
- 現況の再現: `bash scripts/ai/kaggle_final_slots.sh fable take`（読み取り専用。提出はしない）

---

## 1. 用語と前提

- **最終2枠 = 直近2提出**。最終評価はアカウントの最も新しい COMPLETE 提出2件が担当する。新しい提出を
  1本出すたびに、最も古い側の枠が押し出される（FIFO ではなく「新しい2件が残る」）。
- **提出間ノイズ ±20pt**。同一アルゴリズム・同一提出パッケージでも、Kaggle 側ラダーの相手引き当てで
  公開スコアは ±20pt 程度ぶれる（SOT-1902 で md5 一致の再提出により実証済み）。
- **収束スコア**。提出直後の公開スコアは収束途中値（初期値 600.0 付与→ラダーで漸近）。収束判定は
  **ep≥40 + 直近10帯±20pt + W/L均衡**（champion 再提出時の運用値。memory: `sot1887-fable-phase3` 参照）。
- **収束途中の順位は暫定**。収束前スコアで枠の優劣を確定してはならない。

---

## 2. 選定ゲート（最終2枠の決定手順）

### ゲートG0: 候補の収束確認（前提）
枠に載せる各 agent は Kaggle 収束条件（ep≥40 + 直近10帯±20pt + W/L均衡）を満たしていること。
未収束の候補は「収束待ち」とし、収束済み agent 同士で先に2枠を仮確定する。

### ゲートG1: 現行2枠の確定
収束済み agent の中から**収束スコア上位2件**を現行の最終2枠とする。現時点では
**fable（MCTS champion）+ take（ルールベース champion）**。

### ゲートG2: チャレンジャーによる下位枠の入れ替え判定
新しい昇格 agent（debate 等）で下位枠を入れ替えるのは、**次の (a)(b)(c) を全て満たす場合のみ**：

- **(a) 収束スコア条件**: チャレンジャーの**収束スコア**が、現行2枠の**下位**の収束スコアを上回る。
- **(b) league KPI 条件**: チャレンジャーが SOT-1896 のクロスエージェント league KPI（未整備なら事前
  固定した相手混合の集約 **Wilson CI 下限 > 0.5**）でも現行下位枠を上回る。収束スコアと league KPI の
  **両方**で上回ること（片側だけでは入れ替えない）。
- **(c) ノイズ幅条件**: 上回り幅が提出間ノイズ **±20pt を超える**こと。差が ±20pt 以内なら「有意差なし＝
  据え置き」とし、入れ替えない。

3条件のいずれかを欠く場合は **見送り（champion 維持）**。

### ゲートG3: 入れ替え実施時の反映手順
入れ替えを実施する場合のみ：
1. Kaggle exec 互換ゲート（`docs`: `kaggle-exec-runtime-gate` memory）を通す。
2. 「残す枠」→「新チャレンジャー」の順で**連続2提出**する（直近2提出＝意図した2 agent になるよう最後に
   出した2件が最終2枠を占める）。
3. 両提出が `SubmissionStatus.COMPLETE` であること、`kaggle competitions submissions` の直近2件が意図
   した2 agent であることを確認する（`scripts/ai/kaggle_final_slots.sh <a> <b>` で OK 判定）。

---

## 3. 復元手順（計測提出で枠が押し出された場合）

計測・実験目的の提出（例: ume/zero の検証提出、A/B 比較）を出すと、直近2提出が意図した2枠から
ずれる。**復元は「意図した2枠を最後に連続提出し直す」**ことで行う：

1. `bash scripts/ai/kaggle_final_slots.sh fable take` で現況と不一致を確認する。
2. 1日5提出上限に注意し、**意図した2枠のうち枠外に落ちた agent を再提出**する。直近champion が既に
   最新側に居るなら、欠けている1 agent の再提出だけで直近2提出が {再提出, 直前champion} に戻る。両方
   落ちている場合は「残す枠」→「もう一方」の順で2本出す。
3. 再提出後、`kaggle_final_slots.sh` の一致判定が **OK** になることを確認する。
4. **計測提出は最終2枠が確定した後に出さない**運用を徹底する（どうしても必要なら、計測後に必ず復元
   提出をセットで行い、1日の提出枠に復元分を確保しておく）。

> 実 Kaggle への提出操作は**人手ゲート**（SOT-1902 方針: 選定は本Issue、再提出は人間が実行）。本手順書は
> 選定・判定・復元手順の明文化までを担当し、提出そのものは自動実行しない。

## 5. debate への適用判定（G2）

**判定: 見送り（入れ替えなし）。champion 維持。**

- **(a) 収束スコア条件 → 不成立**: debate=523.6。現行2枠の下位（fable ≈571.8収束 / take 575.5）を
  下回る（下位枠に対し −48pt 以上）。
- **(b) league KPI 条件 → 実質不成立**: SOT-1902 で debate の提出パッケージは fable champion と md5 一致
  （差分3ファイルは opt-in 機能が全 OFF で挙動同一）＝ **debate と fable champion は実効同一**。SOT-1903
  の run_discussion.sh 討論でも、他repo で昇格実証された debate 互換候補は**ゼロ**判定（fable第3次
  1892/93/94 全未昇格、zero counter-policy 1879 は neural 非互換で棄却）→ debate に新規の強化は統合
  されておらず、fable champion を超える KPI 上積みは無い。
- **(c) ノイズ幅条件 → 不成立**: 仮に debate を fable と同一視しても差は 0〜ノイズ幅内。上回りは無い。

3条件を1つも満たさないため、debate で下位枠を入れ替える根拠は無い。**据え置き。**

### 再評価トリガ
debate の再評価は、**fable main に新規強化が昇格したとき**に単独で発火する（memory:
`sot1903-debate-integration-selection`）。その時点で debate へ統合 →（収束スコア + league KPI）で
再度 G2 を適用する。それまで debate は最終2枠の候補足り得ない。

## 6. まとめ（運用結論）

1. 最終2枠 = **fable + take**（収束スコア上位2、差はノイズ超で確定的）。
2. debate は G2 全条件不成立で **見送り**（fable 実効同一・昇格上積みゼロ）。
3. 現在アクティブな直近2提出は **fable + ume(452.5)** に displacement 中 → §3 に従い **take の再提出で
   復元**（人手ゲート）。
4. 以後、最終2枠確定後は計測提出を避け、出す場合は復元提出をセットで行う。
